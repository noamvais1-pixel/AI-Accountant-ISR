# AI Accountant ISR · רואה חשבון AI

> Bookkeeping and VAT reporting for an Israeli *osek murshe* (licensed dealer).
> Reads expense receipts with AI, pulls tax invoices from Cardcom, computes the
> periodic VAT return, and generates the PCN874 detailed-reporting file.
> Hebrew RTL interface. Self-hosted, runs locally.

**Stack:** Next.js 15 · TypeScript · PostgreSQL · Prisma · Gemini · Tailwind

**Status:** working, but not battle-tested. The PCN874 file format has not been
validated against the Israel Tax Authority's official validator — see the
warning in [`docs/pcn874.md`](docs/pcn874.md) before filing with it.

**No data included.** This repository contains code only. Scanned documents,
credentials, and the database stay local and are excluded by `.gitignore`.

---

מערכת הנהלת חשבונות לעוסק מורשה: קליטת קבלות מצילום, משיכת חשבוניות מס מקארדקום,
חישוב דוח מע"מ תקופתי, והפקת קובץ הדיווח המפורט PCN874.

## הפעלה

```bash
npm install
npm run db:push
npm run dev
```

המערכת תעלה על <http://localhost:3737>.

לנתוני דמו לבדיקה: `npm run db:seed` (מוחק מסמכים קיימים של עסק הדמו).

## הגדרות סביבה

הערכים נמצאים ב-`.env.local`. `.env.example` הוא התבנית.

| משתנה | למה זה נחוץ |
|---|---|
| `DATABASE_URL` | חיבור ל-Postgres |
| `GEMINI_API_KEY` | קריאת קבלות מצילום. בלעדיו הסריקה מחזירה שגיאה מפורשת |
| `GEMINI_MODEL` | ברירת מחדל `gemini-3.6-flash` |
| `CARDCOM_TERMINAL_NUMBER`, `CARDCOM_API_NAME`, `CARDCOM_API_PASSWORD` | משיכת חשבוניות והפקתן |
| `CARDCOM_DRY_RUN` | `true` חוסם הפקת חשבוניות אמיתיות. ראי למטה |
| `UPLOAD_DIR` | תיקיית הקבצים הסרוקים. ברירת מחדל `./uploads` |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | גיבוי הצילומים לגוגל דרייב. אופציונלי |
| `DRIVE_FOLDER_NAME` | שם תיקיית השורש בדרייב |
| `APP_URL` | כתובת האפליקציה, לבניית ה-redirect של גוגל |

אחרי שינוי ב-`.env.local` צריך להפעיל מחדש את השרת.

### מצב בטיחות בהפקת חשבוניות

`CARDCOM_DRY_RUN=true` (ברירת המחדל) חוסם הפקה וביטול של מסמכים בקארדקום.
חשבונית שהופקה היא מסמך חוקי — אי אפשר למחוק אותה, רק לבטל בחשבונית זיכוי.
כשמוכנים לעבוד באמת, משנים ל-`false`.

## איפה נשמרים הצילומים

**מקומית, תמיד.** בתיקייה שמוגדרת ב-`UPLOAD_DIR` (ברירת מחדל `uploads/`). כל קובץ מקבל
שם אקראי ולא את שמו המקורי — שם קובץ מהדפדפן עלול להכיל `../` ולכתוב מחוץ לתיקייה.
במסד הנתונים נשמר רק המצביע לקובץ, לא הקובץ עצמו.

**ובגיבוי לגוגל דרייב, אם מחובר.** בכל קליטה הקובץ עולה גם לדרייב, לתיקייה מסודרת:

```
רואה חשבון AI/
└── 2026/
    └── 04 יולי–אוגוסט 2026/
        ├── הוצאות/
        │   └── 2026-07-12 מרכז הדפוס הדיגיטלי בעמ 2026-4471 3882.20.png
        └── הכנסות/
```

שם הקובץ בדרייב בנוי כך שאפשר לחפש לפיו בלי לפתוח את המערכת — תאריך, ספק, מספר מסמך וסכום.

### הקמת החיבור לדרייב

פעם אחת, ב-<https://console.cloud.google.com>:

1. צרי פרויקט והפעילי את **Google Drive API**.
2. ב-**OAuth consent screen** בחרי *External* והוסיפי את עצמך כ-*Test user*.
3. ב-**Credentials** צרי *OAuth client ID* מסוג *Web application*, עם redirect URI:
   `http://localhost:3737/api/drive/callback`
4. העתיקי את ה-Client ID וה-Secret ל-`.env.local`, הפעילי מחדש, ולחצי "חיבור לגוגל דרייב"
   במסך ההגדרות.

ההיקף המבוקש הוא `drive.file` בלבד — המערכת רואה ונוגעת **אך ורק בקבצים שהיא עצמה יצרה**.
היא לא יכולה לקרוא שום דבר אחר בדרייב שלך.

### למה OAuth ולא חשבון שירות

לחשבון שירות אין מכסת אחסון משלו, והעלאה לתיקייה של חשבון Gmail פרטי נכשלת. עם Google
Workspace אפשר היה להשתמש ב-Shared Drive, אבל זו לא ההגדרה כאן.

### מה קורה כשדרייב לא זמין

הקליטה מצליחה בכל מקרה. הקובץ שמור מקומית, המסמך מסומן כלא מגובה, ואפשר להשלים הכל
בלחיצה אחת במסך ההגדרות. גיבוי שנכשל אינו סיבה לאבד קבלה.

**ניתוק אינו מוחק כלום.** הקבצים שכבר גובו נשארים בדרייב. גם מחיקת מסמך במערכת לא מוחקת
את הגיבוי — מסמכים עסקיים צריך לשמור 7 שנים, ומחיקה שקטה מדרייב היא בדיוק מה שלא רוצים.

## איך זה עובד

**הוצאות.** מצלמים או גוררים קבלה. Gemini מחלץ ספק, ח.פ, מספר מסמך, תאריך וסכומים,
והמסמך נשמר כטיוטה. שום דבר לא נכנס לספרים לפני אישור אנושי. אחרי האישור המערכת זוכרת
את הסיווג של אותו ספק ומציעה אותו בפעם הבאה.

**הכנסות.** נמשכות מקארדקום לפי טווח תאריכים, **כולל חשבוניות זיכוי**, שנרשמות בסימן
שלילי ומקטינות את ההכנסות ואת המע"מ. הסנכרון בטוח לחזרה — מסמך שכבר נקלט מתעדכן ולא
נוצר פעמיים. אפשר גם להפיק חשבונית חדשה מתוך המערכת, והיא נרשמת מיד בספרים.

**דוח מע"מ.** מחושב לפי התקופה (דו-חודשי או חודשי). המסך מציג את שני הצדדים, את הסכום
לתשלום או להחזר, ורשימת בעיות שימנעו הגשה תקינה. משם מורידים את קובץ ה-PCN874.

### החלטות שכדאי להכיר

**כסף כמספרים שלמים.** כל סכום נשמר באגורות (`Int`). חישוב כספי ב-float צובר שגיאות
עיגול שמופיעות בדוח המע"מ כאגורות שלא מסתדרות.

**עיגול סימטרי.** `Math.round` מעגל 0.5 תמיד כלפי מעלה, ולכן `-118.5` הופך ל-`-118`.
זה שובר את הכלל שחשבונית זיכוי מבטלת במדויק את החשבונית שכנגדה. `roundHalfAwayFromZero`
ב-`lib/money.ts` פותר את זה.

**שיעור מע"מ לפי תאריך.** לא קבוע גלובלי. מסמך מ-2024 מחושב ב-17% ומסמך מ-2025 ואילך
ב-18%, גם כשמפיקים היום דוח על תקופה ישנה.

**הסכומים שנקראו לא "מתוקנים".** אם המשתמש הזין נטו ומע"מ, המערכת לא מחשבת את המע"מ
מחדש. חשבוניות אמיתיות מכילות עיגולים חריגים, ותיקון אוטומטי היה יוצר פער מול המסמך.

**מושכים מקארדקום הכל, ומסננים אצלנו.** התיעוד של קארדקום מגדיר `DocType: -1` כ-"כל
החשבוניות" ובנפרד `-3` כ-"החזרים בלבד", ולא ברור ממנו אם `-1` כולל זיכויים. זיכוי שלא
נמשך היה מנפח את ההכנסות ואת המע"מ לתשלום בשקט. לכן מושכים `-2` (כל המסמכים) ומסננים לפי
`CARDCOM_TYPE_MAP` ב-`lib/cardcom/client.ts` — ההחלטה מה נכנס לספרים היא שלנו, לא פרשנות
למפרט. סוג מסמך שאינו בטבלה מדולג במפורש.

**נקודת אמת אחת לדוח ולקובץ.** `participatesInVatReport` קובעת אילו מסמכים נכנסים לדוח,
ואותה פונקציה מסננת את שורות ה-PCN874. בלי זה הכותרת עלולה להצהיר על מספר רשומות שאינו
תואם את הקובץ, והבודק של רשות המסים ידחה אותו.

**נעילת תקופה שדווחה.** תקופה שסומנה כדווחה נועלת את המסמכים שבה. תיקון נעשה במסמך חדש,
לא בשינוי רטרואקטיבי שיסתור דוח שכבר הוגש.

## מה עוד לא מחובר

**הגשה אוטומטית לרשות המסים.** כרגע מורידים קובץ ומעלים אותו ידנית באזור האישי.
אין ממשק מכונה-למכונה פתוח להגשת PCN874 — בית תוכנה שמגיש בשם לקוחות נדרש לאישור
מרשות המסים ולחתימה דיגיטלית. השלד והתיעוד ב-`lib/tax-authority/provider.ts`.

**מספרי הקצאה.** מטופלים על ידי קארדקום בעת הפקת המסמך, ולכן ההפקה עוברת דרכה ולא
ישירות מולנו. בהוצאות, אם מספר ההקצאה מופיע על החשבונית, ה-OCR קולט אותו והוא נכנס לקובץ.

**ריבוי לקוחות.** הסכימה כבר בנויה סביב `businessId`. המעבר דורש להחליף את
`getActiveBusiness` ב-`lib/services/business.ts` בבחירה לפי סשן, ולהוסיף שכבת הרשאות.

**קליטה ממייל.** ה-enum כבר מכיר מקור `EMAIL`. חסר תהליך שמושך קבצים מצורפים מתיבה ייעודית.

**גיבוי מסד הנתונים.** הגיבוי לדרייב מכסה את הצילומים בלבד. הנתונים עצמם — סכומים, סיווגים,
תקופות — יושבים ב-Postgres המקומי ואין להם גיבוי אוטומטי.
